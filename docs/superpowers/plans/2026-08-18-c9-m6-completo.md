## T1 — El indexer no puede perder notas: transacción por nota

**Por qué**: `indexa()` committea el `mtime` en `notas` *antes* de embeber los
trozos, y no hay transacción envolviendo la iteración. Un fallo a mitad (embed,
lock, kill) deja la nota con mtime fresco y vectores viejos o ausentes, y la
corrida siguiente **la salta para siempre**. El disparador ya ocurrió:
`~/.claude/exo-index.log:13` tiene un `database is locked` real reindexando
`kb-demo/agents`. Sin daño vivo hoy, pero el mecanismo está armado.

### Files

- **Modify**: `engine/src/indexer.rs` — función `indexa` (bucle `for ruta_abs in &rutas_absolutas`, ~línea 95 en adelante).
- **Test**: `engine/tests/indexer.rs` — añadir el test de regresión.

### Interfaces

- **Consumes**: `abre_db(db_ruta: &Path) -> Result<Connection>` (ya existe en el módulo), `rusqlite::Connection::unchecked_transaction(&self) -> rusqlite::Result<Transaction<'_>>`.
- **Produces**: ningún cambio de firma. `indexa(kb: &Path, db_ruta: &Path) -> Result<Resumen>` se mantiene idéntica.

### Pasos

- [ ] **Test primero.** En `engine/tests/indexer.rs` —que ya tiene los helpers
  `kb_fixture()`, `db_temporal()`, `crea_nota()` y `exo::abre_db()`— añade este
  helper y este test. El fallo se inyecta con un **trigger de SQLite** sobre
  `trozos`: dispara *después* del upsert de `notas`, que es exactamente el
  punto del bug, y es determinista (nada de carreras por locks reales):

  ```rust
  fn mtime_de_nota(db: &Path, permalink: &str) -> f64 {
      let conn = exo::abre_db(db).unwrap();
      conn.query_row(
          "SELECT mtime FROM notas WHERE permalink = ?1",
          rusqlite::params![permalink],
          |r| r.get(0),
      )
      .unwrap()
  }

  #[test]
  fn un_fallo_a_mitad_no_deja_la_nota_fuera_del_indice() {
      let kb = kb_fixture();
      let (_tmp, db) = db_temporal();
      indexa(kb.path(), &db).unwrap();

      let permalink = permalinks(&db).iter().next().unwrap().clone();
      let ruta = {
          let conn = exo::abre_db(&db).unwrap();
          conn.query_row(
              "SELECT ruta FROM notas WHERE permalink = ?1",
              rusqlite::params![permalink],
              |r| r.get::<_, String>(0),
          )
          .unwrap()
      };
      let mtime_antes = mtime_de_nota(&db, &permalink);

      // el contenido cambia -> la siguiente corrida DEBE reindexar esta nota
      std::fs::write(
          kb.path().join(&ruta),
          format!("---\npermalink: {permalink}\ntitle: T\n---\ncuerpo distinto\n"),
      )
      .unwrap();

      // fallo inyectado en el paso posterior al upsert de `notas`
      {
          let conn = exo::abre_db(&db).unwrap();
          conn.execute_batch(
              "CREATE TRIGGER falla_trozos BEFORE INSERT ON trozos
               BEGIN SELECT RAISE(ABORT, 'fallo inyectado'); END;",
          )
          .unwrap();
      }

      assert!(indexa(kb.path(), &db).is_err(), "se esperaba fallo al embeber");

      // Sin transaccion por nota, el mtime nuevo ya esta commiteado y la nota
      // queda fuera del indice PARA SIEMPRE: la corrida siguiente la salta.
      assert_eq!(
          mtime_de_nota(&db, &permalink),
          mtime_antes,
          "el mtime avanzo pese al fallo: la nota queda fuera del indice para siempre"
      );
  }
  ```
- [ ] Corre el test y **velo fallar** por la razón esperada (el mtime nuevo SÍ
  está en `notas` pese al fallo):
  `cargo test -p exo --test indexer` desde `engine/`.
- [ ] **Implementación mínima.** En `indexa`, dentro del bucle y justo después
  del `let git_epoch = git_epoch_de(...)`, abre la transacción y haz que
  **todas** las escrituras de esa nota (upsert de `notas`, borrado e inserción
  en `notas_fts`, `reindexa_aristas_de_nota`, `reindexa_trozos_de_nota`) usen
  la transacción; commitea al final del cuerpo del bucle:

  ```rust
  let tx = conn.unchecked_transaction()?;
  // … upsert de notas, notas_fts, aristas, trozos: todo contra `tx` …
  tx.commit()
      .with_context(|| format!("commit de la nota {}", n.permalink))?;
  ```

  `unchecked_transaction` es la variante que no exige `&mut Connection` —
  `conn` aquí es inmutable— y hace **rollback en `Drop`** si no se commitea,
  que es exactamente el comportamiento que queremos ante el `?` de cualquier
  paso intermedio. `Transaction` derefa a `Connection`, así que las llamadas
  `tx.execute(...)` y las funciones que reciben `&Connection` aceptan `&tx`
  sin cambios de firma.
- [ ] Corre el test y **velo pasar**. Corre además la suite entera:
  `cargo test` desde `engine/`, y anota el conteo.
- [ ] **Verifica el ciclo rojo-verde**: revierte el fix (deja el bloque sin
  transacción), corre el test, comprueba que **vuelve a fallar**, restaura el
  fix y comprueba que pasa. Sin esto no es un test de regresión.
- [ ] Commit: `fix(m6): transacción por nota en el indexer — un fallo a mitad ya no saca la nota del índice para siempre`
